# TradeNPC source collection

This repository contains several historical source trees. The root is not a PocketMine-MP plugin. `TradeNPC-Fixed-master/` is now the active API 5 source and the only TradeNPC source built by CI.

| Directory | Manifest API | Attribution and license in that directory |
|---|---|---|
| [`TradeNPC-Fixed-master/`](TradeNPC-Fixed-master/) | `5.0.0` | alvin0319 and DavidGlitch04, GPL-3.0 text retained from the maintained API 5 implementation |
| [`TradeNPC-Fixed-master-api4-legacy/`](TradeNPC-Fixed-master-api4-legacy/) | `4.0.0` | alvin0319 and DavidGlitch04; historical source has no local license file and is not built |
| [`TradeAPI-stable/`](TradeAPI-stable/) | `5.0.0` | nlog, AGPL-3.0 text |

The active [`TradeNPC-Fixed-master/`](TradeNPC-Fixed-master/) source uses [InvMenu](https://github.com/Muqsit/InvMenu), pinned to compatible source in the [build workflow](.github/workflows/build.yml). Its `plugin.yml` declares API 5.0.0. CI checks PHPStan at maximum level against pinned Axolotl-PM 5.0.0 and 5.49.1 source revisions and builds a PHAR with [DevTools](https://github.com/NhanAZ/DevTools). These checks establish compatibility with the tested revisions, not every Axolotl-PM 5.x release. The PHAR gate checks that neither the separate TradeAPI source nor the API 4 legacy snapshot enters the selected plugin artifact. TradeAPI is a historical third-party snapshot in this collection and has no import from the active source.

The archived TradeAPI source passes local PHPStan at maximum level against both pinned server sources. Its [merchant recipe](TradeAPI-stable/tests/merchant-recipes.php), [inventory storage](TradeAPI-stable/tests/inventory-storage.php), [listener guard](TradeAPI-stable/tests/listener-guards.php), [packet header](TradeAPI-stable/tests/packet-headers.php), and [inventory action](TradeAPI-stable/tests/inventory-actions.php) fixtures check specific components. The legacy packet injector now rewrites UI action slots only while this plugin's trade window is current, and unrelated actor events no longer clear its input slots. A separate test PHAR passed isolated startup. A connected client then received matching trade window and offer IDs, and a server-initiated close returned one ingredient without granting an unearned output item. Both pinned server revisions process item stack requests through a different transaction path, and no complete trade through this snapshot has passed. Do not install it as a verified trading plugin or combine the three directories into one PHAR. Their licenses are not interchangeable.

The TradeNPC packet listener ignores pre-login trade packets, invalid recipe indices and incomplete recipes. It checks the combined trade cost and reward capacity in a temporary inventory before changing the player's inventory, leaves normal inventory actions to server validation, and accepts only complete recipe input rows. Trade windows open through the server's per-player inventory API. The [packet guard](TradeNPC-Fixed-master/tests/packet-guard.php), [trade settlement](TradeNPC-Fixed-master/tests/trade-settlement.php), [recipe input](TradeNPC-Fixed-master/tests/recipe-input.php) and [shop NBT](TradeNPC-Fixed-master/tests/shop-nbt.php) fixtures use `AXOLOTL_AUTOLOAD` to select a pinned server Composer autoload file. The NBT fixture checks that two players can open the same NPC inventory.

A connected headless client created one NPC and sent an interaction packet to the selected plugin PHAR on the Axolotl-PM 5.49.1 release server. Before the window fix, the client received a container window with ID 2 and a trade update with ID 1. After the fix, the exact verified CI PHAR sent both packets with window ID 2 and the `trading` window type. A second connected test used a disposable NPC offer of one diamond and one stick for one gold ingot. The client sent a complete trade event, and the server saved the player inventory with the gold ingot after the diamond and stick were consumed. Both processes exited without errors. These tests cover one offer on the tested server revision. They do not verify the Bedrock game UI, other recipes or every Axolotl-PM 5.x release. The separate TradeAPI and API 4 snapshots still require their own analysis and build decisions. No release of this source collection is verified; its root source archive includes code under separate license terms.
